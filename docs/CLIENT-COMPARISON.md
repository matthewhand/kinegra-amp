# Sendspin client comparison

Reviewed 3 November 2026. This compares Kinegra Amp 0.8.44 / code 72 (retaining the timing correction and adding an Android pairing repair), with two upstream implementations; the 0.8.37 failure is retained as a baseline. It is a source comparison, not a listening benchmark or a claim that the reference clients have been verified on this Shield.

The owner reported crackling on 0.8.37. A new regression reproduced incorrect silence insertion despite healthy underrun counters. Version 0.8.38 fixes that reproduced timing-feedback failure and adds adaptive visuals. Its host continuity checks pass; the owner subsequently reported that 0.8.38 was playing well. Sustained combined-load and same-device reference-client comparisons remain pending.

## Evidence and revisions

- **Device:** Kinegra Amp 0.8.37 was installed in place and checked with system media muted. Its own-route Play/Pause/resume, Next and timed-track seek worked; muted delivery checks do not establish sound quality. See [Validation](VALIDATION.md).
- **Host failure:** the current synthetic ramp investigation measured approximately 9.7% unexpected zero frames across 94 zero runs despite zero reported generator underruns. This is a failed continuity check, not a device crackle measurement. The old playback-progress feedback is now a reproduced cause in the host fixture; that does not establish the exact audible artifact on the device.
- **0.8.38:** the original feedback fails the durable regression (31,341 unexpected zero frames, 90 zero runs, seven large jumps, zero generator underruns). The corrected feedback passed 30 seconds of jittered input: 1,379,566 measured frames, zero inserted silence, zero large jumps and zero underruns after startup. Native live checks verify CPU/thermal reporting, automatic detail recovery and manual Audio first; the owner subsequently reported smooth playback. See [Validation](VALIDATION.md) and [continuity regression](../native/tests/test_sendspin_continuity_network.gd).
- **Upstream source:** official Sendspin JavaScript SDK pinned at [`90b158cd3e72165bf7578ffe82750f1b8c3324e1`](https://github.com/Sendspin/sendspin-js/commit/90b158cd3e72165bf7578ffe82750f1b8c3324e1); independent SendspinDroid Android client pinned at [`bd1d90a8f79b8b78c1ee924a0e6c14016ed1f1e2`](https://github.com/chrisuthe/SendspinDroid/commit/bd1d90a8f79b8b78c1ee924a0e6c14016ed1f1e2). GitHub commit/API and files were read at those revisions. Neither was installed, listened to or measured on the same Shield for this comparison.

In the table, upstream capabilities mean **implemented/documented in the pinned source**, not independently verified runtime behavior. A supported or advertised codec is not evidence of what a particular server session negotiated.

## Priority gaps and a fair reference test

1. **Keep continuity acceptance separate from delivery counters.** The new ramp oracle rejects the old feedback and passes 0.8.38. Preserve this regression, underflow/clear tests and the [feedback design notes](../native/ORDERED-CLEAR.md). The owner accepted 0.8.38 listening; retain sustained-load testing rather than treating that report as universal sound-quality proof.
2. **Measure the handoff under visual load.** Compare visuals off/on and controlled stalls, recording PCM continuity, frame time, queue levels, CPU and thermal status. Autoscaling can reduce contention; it cannot repair incorrectly inserted samples or clock accounting.
3. **Evaluate output isolation.** SendspinDroid's dedicated AudioTrack player is the useful architectural reference. Determine whether a dedicated native output path is warranted after the feedback defect is understood; avoid treating a larger buffer as proof of correctness.
4. **Make quality-versus-group-sync explicit if a mode is added.** JS provides a concrete policy comparison. Any unsynchronized local-quality mode must be labelled as such and must not report compliant group sync.
5. **Run a controlled same-device comparison when authorized.** Use the same generic test stream, negotiated PCM format, server/network, HDMI path and output level; record each reference revision/build and actual negotiated format. Compare foreground/background behavior, visuals, pause/resume, seek, reconnect and sustained continuity. Neither upstream client has yet passed this test here.
